# Personal Finance CLI

A small, local-first Python CLI for tracking recurring cash-flow instructions, temporary borrowing between internal buckets, and the payment obligations those actions create.

It is deliberately **not** a budget, expense, investment, net-worth, or bank-account tracker. It does not connect to banks and never transfers money. You make payments manually; this program records which obligations are still outstanding and which you have marked paid.

## What it tracks

The application has four concepts:

- **Buckets** are logical sources and destinations, such as `bucket_a`, `bucket_b`, or `reserve`. Buckets have no balances.
- **Mandates** are recurring monthly instructions, for example `bucket_a → external_destination ₹100.00`.
- **Debts** are actual, temporary borrowings between two existing buckets, for example `bucket_a` owing `bucket_b` ₹1,000.
- **Payments** are individual obligations generated by a salary cycle. Each payment is either `OUTSTANDING` or `PAID`.

The normal mandate flow is:

```text
mandate → salary_credited → payment → outstanding → pay_outstanding → paid
```

For a debt:

```text
actual internal borrowing → debt → monthly debt payment → paid payments
    → debt outstanding reaches ₹0.00 → debt completed
```

## Requirements

- Ubuntu or another system with Python 3
- Python standard library only; no packages need to be installed
- SQLite is included with Python

Run all commands from this project directory:

```bash
cd /home/anirudh-joshi/personal_finance
python3 x.py --help
```

The application uses `finance.db` in this directory. It creates required tables automatically and preserves existing data.

## Configure salary processing

`salary_credited` is protected by a password prompt. The typed password is hidden using Python's `getpass` module. The password is not stored in `x.py` or in the database.

Before running that command, set an environment variable in your terminal:

```bash
export FINANCE_SALARY_PASSWORD='choose-a-strong-password'
```

This setting lasts for the current terminal session. To make it available in future shells, add the export command to a suitably protected shell configuration file, such as `~/.bashrc`, or set it manually whenever needed.

## Everyday workflow

1. Create buckets once, if needed.
2. Create recurring mandates.
3. At salary time, run `salary_credited` once.
4. Review the separately listed obligations with `outstandings`.
5. After completing real-world payments, mark their individual IDs paid with `pay_outstanding`.

Example:

```bash
python3 x.py salary_credited
python3 x.py outstandings
python3 x.py pay_outstanding
python3 x.py show_payments
```

`salary_credited` uses the system month. It records the month after a successful run, so running it again in that same month makes no changes and reports that the cycle was already processed.

## Commands

| Command | Purpose |
| --- | --- |
| `python3 x.py salary_credited` | Generate this month's payment records for active mandates and applicable debts. Requires the configured password. |
| `python3 x.py outstandings` | Show every unpaid payment separately, plus the total. |
| `python3 x.py add_bucket` | Create a logical bucket interactively. `python3 x.py add_bucket name` is also accepted. |
| `python3 x.py show_buckets` | Show active buckets. |
| `python3 x.py add_mandate` | Add a recurring monthly instruction from an active bucket. |
| `python3 x.py remove_mandate` | Disable an active mandate after confirmation. Existing payment history remains. |
| `python3 x.py show_mandates` | Show active mandates. |
| `python3 x.py add_debt` | Record a temporary borrowing between two active buckets. |
| `python3 x.py remove_debt` | Cancel an active debt after confirmation; it stops future debt payments but retains history. |
| `python3 x.py show_debts` | Show active debts and their outstanding amounts. |
| `python3 x.py pay_outstanding` | Mark one or more individual outstanding payment IDs as paid. |
| `python3 x.py show_payments` | Show all payment history, both outstanding and paid. |
| `python3 x.py remove_bucket` | Safely deactivate one bucket if it has no active mandate or debt. |
| `python3 x.py remove_buckets` | Conservatively deactivate all buckets that are currently safe to deactivate. |

## Buckets

Buckets are labels only; they never have a balance or an automatically calculated value. A mandate source must be an existing active bucket, while its destination is free text and may be either a bucket or an external destination.

Examples of valid mandates (using placeholders):

```text
bucket_a   → external_destination
bucket_a   → bucket_b
bucket_c   → external_destination
```

`remove_bucket` does not delete historical data. It refuses to deactivate a bucket while an active mandate uses it as a source or an active debt uses it as a borrower/lender. Historical payment, mandate, and debt references remain intact after a bucket is deactivated.

## Mandates

Use `add_mandate` to enter:

1. Source bucket
2. Destination text
3. Amount
4. Confirmation

An active mandate persists until `remove_mandate` disables it. It is not itself a payment. Each successful salary cycle creates a new payment record from its current source, destination, and amount. Future mandate changes never overwrite historical payment records.

## Debts and rounding

Use `add_debt` only for an actual temporary borrowing between two existing active buckets. It asks for:

1. Borrower bucket — the bucket that owes money
2. Lender bucket — the bucket that supplied it
3. Amount
4. Repayment months
5. Confirmation

For example, a ₹1,000 debt over 3 months is generated at approximately ₹333.33 for normal monthly payments, with the final payment adjusted by a few paise if necessary. Internally, debt calculations use whole paise and `Decimal` conversion so paid debt payments total exactly the original amount.

Debt payments are generated only while the debt is active and has repayment amount remaining. Marking a debt-linked payment as paid reduces that debt's outstanding amount. Once it reaches ₹0.00, the debt is made inactive/completed and can no longer generate payments. Cancelling a debt with `remove_debt` also stops future payments but does not remove its historical payments.

## Paying obligations

First inspect outstanding records:

```bash
python3 x.py outstandings
```

Then select individual payment IDs when prompted. Multiple IDs are separated by spaces:

```text
Select payment IDs to mark as paid: P001 P003
Confirm? [y/N]: y
```

Invalid IDs and IDs that are already paid are reported without crashing. Payments are never consolidated: each generated obligation retains its own ID and status.

## Data and safety

- `finance.db` is local SQLite data. Back it up periodically before making major changes:

  ```bash
  cp finance.db finance.db.backup
  ```

- The program uses non-destructive active/inactive status for removed buckets, mandates, and debts. It does not delete payment history.
- The `payments` table records source, destination, amount, type, associated mandate/debt, salary month, status, and timestamps.
- The `salary_runs` table prevents accidental duplicate generation for a month.
- For isolated experimentation or testing, point the program at another database file:

  ```bash
  FINANCE_DB_FILE=/tmp/finance-test.db python3 x.py show_buckets
  ```

  Do not set this variable for normal use unless you intentionally want a different database.

## Important limitations

This is a simple manual tracker. It does not verify that salary was received, that a bank transfer happened, or that an outstanding payment is correct in the real world. It only records the instructions and payment status you enter.

Do not treat its bucket names as account balances, budgets, or spending categories. There are no automatic transfers, bank integrations, notifications, charts, web UI, or cloud synchronization.
